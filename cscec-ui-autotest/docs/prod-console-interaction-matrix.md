# 生产控制台交互层级矩阵

本文档用于回答两个问题：生产控制台有哪些可验证交互，以及现有自动化实际走到了哪一层。
当前版本仅依据代码、pytest 收集结果、资产登记和既有文档进行静态盘点；未重新访问生产页面，也未修改业务测试。

- 盘点日期：2026-09-14
- 目标环境：PROD
- 控制台域名：`https://irp.cscec.com/`
- 租户口径：中建云
- 当前账号口径：以账号实际可见菜单为准，暂不把具体角色作为断言条件
- 生产选择器：`smoke and readonly`

## 1. 矩阵口径

### 1.1 交互层级

| 层级 | 定义 | 典型证据 |
| --- | --- | --- |
| L0 | 域名、认证、会话可用 | 登录成功，未跳回 IAM |
| L1 | 入口或页面外壳可见 | 菜单、标题、页面主容器可见 |
| L2 | 页面首层只读交互 | 搜索、筛选、分页、普通 Tab、展开收起 |
| L3 | 业务对象详情 | 点击列表行、详情、抽屉、编辑页只读回显 |
| L4 | 详情内部交互 | 详情 Tab、权限树、流程图、历史记录、嵌套页面 |
| L5 | 写操作前置探查 | 新增、删除、提交、申请等弹窗或确认页打开，但不确认 |
| L6 | 受控真实写入 | 只允许明确授权的测试数据与业务范围 |

层级记录的是单条路径实际达到的最高层级，不因同一模块的其他用例更深而自动提高。

### 1.2 入口类型

| 标记 | 含义 |
| --- | --- |
| UI | 从用户可见入口逐级点击 |
| DIRECT | 直接访问业务路由，不能证明菜单入口可用 |
| HYBRID | 先打开门户或控制台，再由辅助方法直达页面 |

### 1.3 退出风险

| 标记 | 含义 |
| --- | --- |
| N | 未发现跳过或静默放行逻辑 |
| P | 存在 `pytest.skip`，生产必跑时可能不失败 |
| S | 存在软通过：控件、数据或详情缺失时继续执行，或断言允许列表/空态代替目标对象 |

### 1.4 浏览器健康监控

`Health=Y` 表示交互期间已经统一监听 `console.error`、`pageerror`、404 和 5xx。
`Health=N` 表示主要依赖页面文案或 URL 断言，仍可能漏掉接口为 200 但前端渲染失败的情况。

## 7. 建议实施顺序

本矩阵审核通过后再开始代码阶段，每轮只处理一个边界明确的批次：

1. 先治理共性门禁：生产 `skip` 策略、健康监控、动作发生证据，不新增业务范围。
2. 权限管理补齐：角色成员、数据权限、编辑确认前探查，再覆盖登录/用户/租户管理。
3. 资源管理补齐：先从左侧菜单建立真实路径，再覆盖数据资源管理的列表、详情和只读 Tab。
4. 系统配置按 6 个二级菜单逐页实施，每次 2 个页面。
5. 评价、计量、运维、运营按菜单组分批实施。
6. 订阅、订单、审批、工单把已有候选稳定化，消除软通过后再晋级生产默认。
7. 最后建立 L5 确认前操作矩阵；真实写入继续放在独立显式套件。
