## 遇到的问题与解决方案

### 问题1：.docx 文件读取受限

**现象**: `python -c "import zipfile..."` 被 sandbox hook 阻止
**原因**: PreToolUse:Callback 检测到 Python 命令中的某些模式被 blocklist 匹配
**解决**: 改用 `unzip -p "file.docx" word/document.xml` 直接提取XML
**优化建议**: Skill 中应将此方案作为唯一推荐方案，不再尝试 Python 方案

### 问题2：sed 命令路径被误判

**现象**: `sed -n 's/<[^>]*>//gp' | sed '/^$/d'` 被拒绝
**原因**: sandbox 将 sed 的正则表达式 `/^$/d` 误判为文件路径
**解决**: 不使用 sed 后处理，直接读取原始 XML 并在上下文中解析
**优化建议**: 避免在 Bash 中使用复杂管道，特别是含有 `/` 开头模式的命令

### 问题3：子任务超时

**现象**: M6-M10+E2E 子任务运行超过 10 分钟后超时
**原因**: 单个子任务覆盖模块过多（6个模块 + E2E），生成量过大
**解决**: 在主线程中直接完成该部分用例
**优化建议**:
- 子任务粒度控制在 2-3 个模块/组，预估生成量 40-60 条以内
- 设置 timeout=300000（5分钟），超时后主线程接管
- 推荐拆分策略：组1(M1-M3 ~54条)、组2(M4-M5 ~56条)、组3(M6-M8 ~32条)、组4(M9-M10+E2E ~32条)

### 问题4：Excel 模块名匹配错误

**现象**: M10 的 10 条用例被错误归入 M1（因 "M10" 包含 "M1" 前缀）
**原因**: 用 `if key in line` 做模块检测，M1 在 M10 之前匹配
**解决**: 改用正则 `\bM10[\s.\-—·]` 精确匹配，且长前缀优先
**优化建议**: 检测模块时必须按 key 长度降序排列: M10 → M9 → M8 → ... → M1

### 问题5：Markdown 表格解析遗漏

**现象**: M5 模块首次解析少 2 条用例
**原因**: 子章节标题（如 `### M5.7 边界`）未正确保持父模块上下文
**解决**: 确保 `###` 级标题不覆盖当前模块上下文
**优化建议**: 仅 `##` 级标题触发模块切换，`###` 级继承父模块

### 问题6：临时文件读取被 sandbox 阻止

**现象**: `Read file_path="C:\Users\...\tasks\xxx.output"` 被拒绝
**原因**: 文件路径在 vault 目录之外
**解决**: 使用 `TaskOutput` 工具等待子任务结果
**优化建议**: 不要尝试直接读取子任务输出文件，始终用 TaskOutput

### 问题7：步骤/预期结果列用了 `<br>` 而不是真换行

**现象**: 详细测试用例中的“步骤”“预期结果”列使用了 `1.` + `<br>` 的形式，阅读和 Excel 落地都不够稳定
**原因**: 直接沿用了 GFM 表格单元格的兼容写法，没有把“真实换行”和“固定序号样式”作为硬约束
**解决**:
- 步骤、预期结果、前置条件的多行内容统一保存为真实换行
- 序号统一写成 `【1】`、`【2】`、`【3】`
- 详细用例 `.md` 优先输出为 HTML table，避免 GFM 表格对单元格内真实换行支持不足
**优化建议**:
- 导出 Excel 前增加格式检查：禁止出现 `<br>`；禁止出现 `1.`、`2.` 这类序号
- `gen_excel.py` 同时兼容 Markdown table 和 HTML table，并保留单元格内换行

## 用例设计高价值模式

### 状态组合矩阵
当需求包含多维度状态时（如 生效状态×审批状态），必须穷举所有组合：
```
4种组合 = 2(生效/未生效) × 2(无审批/审批中)
每种组合验证: 可编辑性 + 可提交性 + 展示数据 + API返回数据
```

### 状态流转全路径
识别所有从初始状态到最终状态的路径，特别关注：
- 正常路径（happy path）
- 驳回后重提路径
- 连续操作路径（驳回→修改→重提→通过）

### 联动测试
当字段A的变更触发字段B/C/D的清空或变更时：
- 变更前验证（确认B/C/D有值）
- 执行变更
- 变更后验证（确认B/C/D被正确清空）
- 重新填写验证（确认新的B/C/D限定在正确范围内）

### 越权测试
每个权限控制点都应有"前端+后端"双重测试：
- 前端：按钮不可见/不可点击
- 后端：直接调API返回403

## 未来优化方向

1. **模板化输出**: 支持不同项目的输出模板（不仅限于中建云）
2. **增量更新**: 当需求变更时，只更新受影响的用例，不重新生成全部
3. **用例与需求追踪**: 建立用例→需求的双向追踪矩阵
4. **自动化集成**: 生成的用例可直接导入 TestRail / Jira / Excel Online
5. **知识库缓存**: 首次读取后缓存基线摘要，后续执行跳过阶段0
